## 一、产品定位优化

### 1.1 当前定位问题

当前定位为「AI 个人衣橱 MVP」——用户上传衣物图片，系统识别衣物属性，维护数字衣橱，并基于衣橱生成搭配、分析购买决策、获取购物推荐。

核心问题：
- 「AI 个人衣橱」听起来偏工具，用户不知道为什么要马上用
- 「维护数字衣橱」前置成本高，录入 50 件衣服需操作 50 次
- 「AI 搭配」用户天然质疑准确性
- 「购物推荐」容易被用户认为是导购广告
- 「AI 换装」暂未开放，不能作为主卖点
- 功能很多，但用户第一动作不够明确

### 1.2 新定位

**对外定位**：AI 买衣服避坑助手

**一句话描述**：上传想买的衣服，AI 帮你判断值不值得买、会不会闲置、衣柜里有没有类似款、能不能搭出多套。

**核心价值**：
1. 帮用户减少冲动消费
2. 帮用户避免买重复款
3. 帮用户提高衣服利用率
4. 帮用户发现衣橱缺口
5. 帮用户从「被种草」变成「理性购买」

### 1.3 产品关键词

**主推**：买衣服避坑 · 衣柜重复检测 · 下单前分析 · 衣服闲置风险 · 购物冷静器 · 衣橱缺口分析 · AI 穿搭建议 · 搭配利用率

**不主推**：AI 个人衣橱 · AI 换装 · 智能衣柜 · 虚拟试衣 · 电商导购

### 1.4 目标用户

**第一优先**：20-35 岁女性，喜欢淘宝/小红书/抖音种草，经常买衣服但容易买重复、买回来不穿、不知道怎么搭。

**第二优先**：通勤女性——上班穿什么、如何少买但搭配更多、如何建立基础款衣橱。

**第三优先**：小红书穿搭博主、女装店主、买手店主（后期可转 B 端）。

## 二、核心用户动线重设计

### 2.1 当前路径

注册/登录 → 上传衣服 → AI 识别 → 衣橱管理 → 搭配生成 → 购物推荐

问题：上传衣橱前置成本高，用户必须先投入后获得价值。

### 2.2 新路径

```
用户被种草
    ↓
上传商品图 / 粘贴商品链接
    ↓
AI 买前分析 → 得到结论（推荐/考虑/跳过 + 分数 + 风险）
    ↓
发现衣橱有重复 → 自然引导上传常穿衣服
    ↓
上传 5-10 件常穿衣服 → AI 生成更准确建议
    ↓
衣柜体检报告 → 缺口推荐 → 形成长期使用闭环
```

### 2.3 新用户首次体验（免注册）

1. 落地页核心动作：「上传想买的衣服，看看值不值得买」
2. 未登录可免费分析 **1 次**，结果展示完整价值（分数、风险、搭配潜力）
3. 第 2 次分析弹窗引导登录
4. 7 天内累计 **3 次**游客分析
5. 登录后引导「上传 5 件常穿衣服」提升准确度

### 2.4 主导航简化

当前 7 个入口 → 优化为 **5 个核心入口**：

| 导航项 | 说明 | 对应视图 |
|--------|------|---------|
| 🏠 首页 | 买前分析入口 + 今日穿搭推荐 | HomeView |
| 👗 衣橱 | 衣物列表 + 概览面板 | WardrobeView |
| 🧪 搭配 | AI 搭配生成 + 指定单品搭配 | OutfitView |
| 📊 报告 | 衣柜体检 + 缺口分析 | ReportView (新) |
| 📋 历史 | 分析历史 + 搭配历史 | HistoryView |

**AI 换装**从主导航移除，仅在购买分析结果页底部作为「即将开放」预告，附带内测等待名单。

### 4.2 后端 AI 输出结构化 Schema

```python
{
  "conclusion": "recommend | consider | skip",
  "score": 76,                        # 0-100
  "summary": "一句话总结",
  "dimensions": {
    "outfit_potential": 82,
    "scene_match": 78,
    "gap_fill": 61,
    "duplicate_risk": 45,             # 反向分
    "idle_risk": 58                   # 反向分
  },
  "pros": ["颜色百搭", "适合通勤"],
  "cons": ["已有类似款", "版型普通"],
  "similar_items": [
    {"garment_id": "...", "name": "灰色针织衫", "similarity": 0.82}
  ],
  "outfit_ideas": [
    {
      "scene": "通勤",
      "items": [{"category": "top", "image_url": "...", "reason": "..."}],
      "reason": "颜色协调，风格统一"
    }
  ],
  "idle_risk_detail": {
    "level": "中",
    "reason": "颜色百搭但已有类似款"
  },
  "suggested_price": {"min": 80, "ideal": 150, "max": 250},
  "next_actions": ["save", "share", "analyze_another"]
}
```

### 4.3 AI 语气规范

- 直接、克制、像理性朋友
- 不夸不煽动购买冲动
- 多提醒风险，少制造 FOMO
- 每个结论必须有原因
- 承认不确定性（如「由于只有商品图，无法判断面料质感和上身版型」）

### 4.4 购物冷静器

分析前可选填：「你为什么想买这件？」选项：被博主种草 / 觉得好看 / 缺这个品类 / 打折 / 上班需要 / 约会旅行需要 / 不确定

不同原因影响分析结果。如选择「打折」→ AI 提醒「打折不是购买理由，关键是你是否真的会穿」。

### 4.5 收藏夹批量分析

一次上传 5-10 张商品截图 → AI 排序分类：

- 建议购买：X 件
- 可以考虑：X 件
- 建议跳过：X 件
- 预计可避免浪费：约 ¥XXX

### 4.6 替代款建议

当 AI 不建议购买时，输出：「不建议买这件，但你真正缺的是：浅色直筒裤 / 基础内搭 / 通勤鞋」，自然连接缺口推荐。

## 五、上传流程优化

### 5.1 统一上传中心

不区分后端接口，用户按目的选择：

| 入口 | 用途 |
|------|------|
| 🛍 我想买的商品 | 买前分析入口 |
| 👗 我已有的衣服 | 衣橱入库 |
| 👔 我今天穿的搭配 | 穿搭分析入口 |
| 📱 小红书/淘宝截图 | 直接进入分析 |
| 📸 衣柜照片 | 一张拍多件 → 拆分识别 |
| 🔗 粘贴商品链接 | URL → 抓取图片 → 分析 |

### 5.2 上传方式优先级

| 优先级 | 方式 | 说明 |
|--------|------|------|
| P0 | 商品截图/图片上传 | 最符合真实使用习惯 |
| P0 | 粘贴商品链接 | URL → 后端抓取 → 分析 |
| P1 | 已有衣物批量上传 | 一次选 10-20 张，逐张确认 |
| P1 | 衣柜照片拆分识别 | 一张拍多件 → AI 拆分 → 逐件确认 |
| P1 | 穿搭照片分析 | 上传穿着照 → AI 评价 |
| P2 | 商品链接批量分析 | 一次粘贴 3-5 个链接 |

### 5.3 上传过程提示

替代「识别中」：

```
正在识别品类... → 正在分析颜色和风格... → 
正在判断搭配潜力... → 正在对比你的衣橱... → 
生成购买建议 ✓
```

每步有进度动画和预估剩余时间。

### 5.4 识别失败处理

| 恢复路径 | 场景 |
|----------|------|
| 🔄 重新上传 | 图片质量不够 |
| ✋ 手动选择品类 | AI 无法确定品类 |
| ✂️ 手动裁剪区域 | 背景太杂、多件同框 |
| ⏭ 跳过识别，手动填写 | 用户不想等 AI |
| 📖 查看失败原因 | 用户想知道为什么 |

失败文案：「这张图里的衣服不够清晰，我没能准确识别。你可以重新上传商品主图，或手动选择品类继续分析。」

## 六、衣橱管理模块优化

### 6.1 新定位

**衣橱 = 个人穿搭数据库 + 购买决策依据 + 衣柜体检报告**

### 6.2 衣橱首页改为概览面板

│                                              │
│ 🚫 本月不建议再买：灰色上衣 · 黑色半裙           │

### 6.3 衣物列表增强

| 增强项 | 说明 | 优先级 |
|--------|------|--------|
| 常穿/偶尔/闲置标记 | 每件衣服用户可标记使用频率 | P1 |
| 一键标记最常穿 5 件 | 新用户快速建立风格画像 | P0 |
| 重复品类提醒 | 同品类 + 同色系超过 N 件时高亮 | P1 |
| 自然语言搜索 | 「适合约会的上衣」「冬天黑色外套」 | P1 |
| 批量编辑 | 批量改标签、季节、归档 | P1 |
| 换季归档 | 过季衣物归档，默认列表不展示 | P2 |

### 6.4 衣物关系网络

每件衣物详情页展示：
- 可搭配单品列表
- 不适合搭配的单品
- 相似单品（含相似度）
- 替代单品
- 适合的场景

### 6.5 冷启动：虚拟基础衣橱

新用户注册后立即赠送 **12 件通用虚拟基础款**：
白T恤 · 条纹衫 · 牛仔裤 · 黑色西裤 · 米色半裙 · 白衬衫 · 风衣 · 黑色西装 · 运动鞋 · 帆布鞋 · 黑色托特包 · 细腰带

目的：零上传即可体验搭配生成、购买对比等核心功能。

## 七、搭配生成模块优化

### 7.1 场景入口改写

从「选场景生成搭配」→ **「你今天为什么需要搭配？」**

场景扩展为 10+：上班 · 约会 · 见客户 · 逛街 · 运动 · 拍照 · 旅行 · 聚餐 · 不知道穿什么 · 想把某件衣服搭出来

支持自定义场景（如「海边度假 3 天」）。

### 7.2 指定单品搭配（P1，高价值）

用户选一件已有衣服或想买的商品 → AI 生成 5 种方向：

| 方向 | 说明 |
|------|------|
| 最稳妥 | 不会出错的日常穿法 |
| 更显气质 | 提升质感的搭配 |
| 更休闲 | 周末放松感 |
| 更适合拍照 | 上镜效果优先 |
| 更适合通勤 | 干练职业感 |

### 7.3 搭配理由（每套必备）

```
为什么这么搭？
· 颜色：灰色冷调与牛仔裤蓝色系协调
· 风格：通勤休闲两不误
· 场景：办公室、咖啡馆、周末逛街
· 风险：开衫偏短款，配低腰裤可能露腰
· 替换：没有帆布鞋？换成小白鞋效果接近
```

### 7.4 不喜欢反馈机制

负反馈必须选择原因（不能只点「不喜欢」）：

太普通 · 太成熟 · 太幼稚 · 不适合上班 · 不显瘦 · 颜色不喜欢 · 不是我的风格 · 天气不合适 · 没有这类鞋/包 · 不想穿裙子/裤子

反馈数据沉淀为风格画像。

### 7.5 搭配模板

用户可保存固定搭配模板：上班常穿 · 约会常穿 · 周末常穿 · 旅行常穿 · 拍照常穿。后续 AI 生成优先参考。

### 7.6 温度档位细化

| 温度区间 | 搭配策略 |
|----------|----------|
| ≤5°C | 厚外套 + 内搭 + 保暖层 |
| 5-15°C | 风衣/大衣 + 长袖 |
| 15-25°C | 薄外套/单层长袖 |
| ≥25°C | 短袖/轻薄面料 + 防晒 |

## 八、穿搭分析（新增模块）

### 8.1 定位

与「买前分析」互补：

| | 买前分析 | 穿搭分析 |
|------|----------|----------|
| 对象 | 想买的商品 | 自己穿着的照片 |
| 目的 | 值不值得买 | 穿得好不好看 |
| 输出 | 购买建议 | 穿搭评价 + 改进方案 |

### 8.2 使用场景

- 出门前纠结：「今天这一身到底行不行？」
- 对镜自拍后：「这样搭会不会太普通？」
- 买了新衣服后：「这件新衣服怎么融入衣柜？」
- 整理衣柜时：「这件衣服我穿起来到底怎么样？」

### 11.2 个性化画像字段（P1）

基础：身高 · 体重 · 体型（苹果/梨形/H型等）· 肤色 · 常穿尺码
偏好：喜欢/避雷的风格 · 颜色 · 场景优先级

### 11.3 LLM 动态画像引擎（P1）

**为什么需要 LLM**：用户手动填写有限且不一定准确，LLM 从行为数据中推断更真实的偏好。

**工作方式**：

```
用户行为数据（上传/收藏/负反馈/购买分析/穿搭分析/常穿标记/浏览点击）
        ↓ 每周/每月喂给 LLM
LLM 输出结构化画像
  ├─ 风格人格描述（自然语言）
  ├─ 偏好向量（各风格/颜色/品类的权重）
  ├─ 隐性需求推断
  └─ 变化趋势（风格是否在演变）
        ↓ 存入 UserProfile
下游功能消费（搭配生成/购买分析/购物推荐注入为 system prompt 约束）
```

**LLM 画像输出 Schema**：

```python
{
  "persona_text": "你偏好简约通勤风，喜欢黑白灰驼等中性色...",
  "style_weights": {"通勤": 0.82, "简约": 0.78, "法式": 0.35, ...},
  "color_affinity": {"黑": 0.90, "白": 0.85, "灰": 0.72, ...},
  "inferred_needs": [
    "数据表明你对有设计细节的单品更愿意保存",
    "近 3 月运动场景覆盖持续下降"
  ],
  "trend": {
    "direction": "从纯通勤向轻法式过渡",
    "confidence": 0.65,
    "evidence": ["最近 3 次收藏含法式元素", "上传了 2 件条纹衫"]
  }
}
```

**触发时机**：
- 用户上传 5 件以上新衣物
- 用户给出 10 次以上搭配反馈
- 每周定时任务
- 用户主动触发「重新分析我的风格」

**画像注入 Prompt 示例**：

```python
SYSTEM_PROMPT = f"""
你是穿搭助手。当前用户画像：
- 风格偏好：{weights}，避免权重 < 0.2 的风格方向
- 颜色亲和：{colors}，避免亲和度 < 0.15 的颜色作为主色
- 体型：梨形，避免紧身短裤和强调臀部的剪裁
- 预算敏感：优先使用衣橱已有单品
- 风格过渡期：可少量试探法式方向
"""
```

**用户可见 + 可修正**：画像对用户透明展示，支持「准确/不准确」反馈和手动修正。

### 11.4 从行为中学习（隐性信号）

## 十八、最终产品闭环

```
用户被种草
    ↓
上传商品图/链接
    ↓
AI 判断是否值得买
    ↓ （信息不足时）
引导上传 5-10 件常穿衣服
    ↓
AI 生成更准确的购买建议
    ↓
系统发现衣橱重复和缺口
    ↓
用户查看衣柜体检报告
    ↓
系统推荐真正值得补的单品
    ↓
用户保存、购买或跳过
    ↓
下次想买衣服时再次回来分析 ← 闭环
```

**核心原则**：用户不是想维护衣橱，用户是想少买错衣服。

## 附录 B：关键设计决策记录

| 决策 | 理由 |
|------|------|
| 不主推「AI 换装」 | 当前能力未就绪，夸大宣传会降低信任 |
| 早期推单次付费非订阅 | 先验证付费意愿，再升级会员 |
| 新增「穿搭分析」模块 | 与买前分析形成互补，覆盖种草→穿着的全链路 |
| 保留「衣橱」但从主导航弱化 | 衣橱是数据基础但不能是主入口 |
| LLM 画像在 P1 而非 P0 上线 | 需要 1-2 个月行为数据积累才有效 |
| 微信小程序列为 P0 | 国内推广的核心落地载体 |
| 主导航 5 项 | 买前分析 + 衣橱 + 搭配 + 报告 + 历史 |
