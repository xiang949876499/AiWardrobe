# AI 婚礼 MV P0 实现计划

> 目标：在独立分支 codex/ai-wedding-mv 中，将已评审的婚礼 MV spec 实现为可运行的端到端 MVP。实现必须保持现有 AiWardrobe 的登录、衣橱和推荐功能不回归。
>
> 规格来源：docs/superpowers/specs/2026-10-01-ai-wedding-mv-design.md
> 当前状态：演示业务工作流已实现并通过自动测试；原始产品 Spec 的 P0 尚未全部完成。真实模型、自动脚本/静帧、音乐库和版本回退等缺口见[完成情况核查](../../wedding-mv-completion-audit-2026-10-01.md)。

## 范围及约束

- 交付独立的婚礼 MV 工作区：项目、双方授权、照片素材、爱情故事、脚本与分镜、生成任务、镜头审查、版本记录、预览导出。
- 使用现有 FastAPI、SQLAlchemy、React/Vite、存储抽象和测试体系。
- 支持演示/本地运行链路；外部模型调用通过 provider 接口封装。未配置有效供应商凭证时，显式报告不可用，不伪造生成成功或费用。
- 支付、生产级模型账户、授权音乐曲库属于外部前置条件；未配置时默认禁用并安全失败。
- 租户隔离、参与者作用域、授权门禁、预算上限及私有媒体访问作为上线前安全条件。

## 执行任务

### Task 1: 后端领域模型与授权 API

- 定义 WeddingProject、Participant/Consent、WeddingAsset、StoryVersion/Fact、StoryboardShot、GenerationJob/ShotCandidate、RenderVersion、BudgetLedger、AuditEvent。
- 状态使用受控枚举并限制非法跃迁；保存项目版本、参与方、当前审阅人及时间戳。
- 使用已有 schema 初始化方式兼容开发和测试数据库；为新增字段设计轻量迁移。
- 验证级联删除和私有素材元数据不意外泄漏。

- 新增独立路由，提供项目 CRUD、邀请与确认、故事/分镜提交与审阅、额度与报价、生成任务、单镜头修改、预览与导出、删除。
- 所有访问先校验 owner 或受限 participant scope；邀请 token 仅存哈希、单次兑换并过期。
- 文件真实 MIME、尺寸和格式在服务端校验；使用私有存储及授权下载端点。
- 所有生成或外发任务均核验双方有效授权、静帧确认、预算及当前内容版本。
- 记录审计、模型供应商调用、错误分类和预算预占/结算。

### Task 2: AI/媒体服务及异步状态

- 为故事转结构、静帧、人物视频和场景视频定义 provider 协议与配置；生产 provider 缺少凭证时返回明确的 unavailable 状态。
- 添加可复现的本地 demo provider，不得把 demo 结果标记为真实 AI 成片。
- 生成作业持久化，呈现 queued、processing、review、failed、completed 等真实状态，并支持重试幂等及局部失败恢复。
- 用 FFmpeg 服务生成照片镜头、字幕、背景音乐与最终 MP4；缺少 FFmpeg/授权曲库时明确报错，不输出伪完成文件。
- 将单次与累计成本写入账本，并在实际供应商调用前预占且执行项目/账户硬上限。

### Task 3: 前端用户流程

- 增加婚礼 MV 独立入口，不替换衣橱主流程。
- 实现新建项目、双人授权、素材上传、故事填写、事实与分镜确认、生成进度、逐镜头审核/修改、成片预览与导出。
- 前端操作服从后端状态和权限，不自行推导成功；刷新后从 API 恢复当前进度。
- 显示混合照片与 AI 镜头的比例、预算、服务可用状态和失败原因。

### Task 4: 验证、文档与交付

- 新增覆盖权限隔离、授权撤销、token 重放、预算超限、非法状态跃迁、上传校验、任务重试与删除的后端测试。
- 新增关键前端流程的测试，并运行现有后端/前端测试和生产构建。
- 更新环境配置样例、API/运行说明和产品文档，记录未配置的外部服务限制。
- 审查差异和安全边界；不推送、不创建 PR、不启用付费供应商。

## 完成判据

- 新用户能经现有登录创建婚礼项目并完成 demo 模式流程；另一方能经邀请只访问被授权的项目/素材。
- 未授权、已撤销、版本过期、余额超限的请求会被服务端拒绝。
- demo 与真实生成明确区分；真实供应商不可用时任务显示失败/不可用，而不是假装成功。
- 后端全套测试、前端测试和生产构建通过，或明确列出环境阻断项。

## 实施结果（2026-10-01）

- Task 1–3 的演示基础已实现：项目/授权 API、媒体任务 worker、预算及生成任务过期恢复、独立私密婚礼工作区、邀请者会话隔离、逐镜审核、单镜头重做和导出门禁。模型协议不代表真实供应商接入；渲染崩溃恢复仍未实现。
- Task 4 已交付配置和测试基础：独立 S3 私有 bucket、Compose worker/FFmpeg、Windows 本地 worker 启动、环境变量和运行/API 文档；完整环境端到端验收仍待执行。
- 前次本地检查：后端 `python -m pytest -q` 122 passed；前端 `npm test` 36 passed；`npm run build` 通过；Compose YAML 解析和 `git diff --check` 通过。本轮复查结果见完成情况核查。
- 任一方撤回授权会取消排队、处理中、待审及已批准渲染，清除可下载版本引用；媒体读取和导出都会重新核验双方授权。worker 在轮询前初始化数据库，并在持久化成片前检查取消状态。
- 环境限制：Docker CLI 未安装，未能实际构建/启动 Compose 镜像；当前无 PostgreSQL，因此未验证真实 PostgreSQL 行锁行为。真实模型适配器和授权音乐未启用，也未进行外部或付费调用。
