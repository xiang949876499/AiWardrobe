# AiWardrobe 优化实现计划

> 依据 [优化 Spec](../specs/2026-10-01-aiwardrobe-optimization-spec.md)，在 `codex/aiwardrobe-optimization` 分支实施。`[x]` 表示该项代码与本地验证完成，`[~]` 表示环境验收或部分行为尚未完成。2026-10-01 审核发现的 R1～R8 已修复并完成本地复验，证据见[修复报告](../../reviews/2026-10-01-optimization-fix-verification.md)；PostgreSQL、真实供应商和完整无障碍验收仍不能标为通过。

## M1：真实链路可靠

- [~] 建立版本化数据库迁移入口；历史字段和数据使用显式迁移，不再依赖启动时临时 `ALTER`。SQLite 新库/旧库已有测试；PostgreSQL 新库/旧库未在本机执行。
- [x] 修正真实 AI/provider 错误语义与来源；真实调用失败不伪装为 demo，机器结果保持待确认，并保存结构化错误和来源元数据。
- [x] 统一图片校验、预处理、缩略图和安全 URL 下载；限制协议、DNS/IP、重定向、MIME、文件/像素大小并保留 PNG 透明度。
- [x] 引入私有 StoredAsset 和受控访问；资产授权后生成短期签名 URL，并依据引用和保留期回收。
- [x] 建立 AnalysisTask/ProviderOperation 持久任务、幂等、阶段、租约和受限运维操作；仅失败且提交安全的任务可原子重试。可查询供应商 ID 立即持久化，重启后只读恢复，取消后的迟到结果不得入库；本地模拟契约已验证。
- [x] v2 衣橱上传、默认购买 URL/图片和推荐分析共用任务服务；旧 API 是最多 20 秒的同步适配层，共享配额及幂等。本地默认启动独立 API/worker/frontend，真实进程上传到确认冒烟通过。
- [~] 增加生产 JWT 校验、原子配额、隔离滑动窗口、错误码和安全日志。SQLite 测试通过；PostgreSQL 并发行为未在本机验证。

## M2：购买决策闭环

- [x] 添加 decision context/revision、购买快照、结构化偏好、候选价格/决定/拥有状态和历史查询。
- [x] 确定性购买规则按维度提供 evidence/coverage，缺失证据保持 null；前端兼容正常、空衣橱、超预算和未知价格的真实后端契约。
- [x] 普通搭配与购买候选组合使用实际确认衣物 ID、归属、排除项及季节交集；无有效组合允许零组。季节分桶避免无效笛卡尔积，末尾有效衣物不会被截断。
- [x] 保存/人工关联/删除共用唯一规范关系、User-first 锁顺序和持久幂等回执；旧候选需明确核对，删除保留墓碑。SQLite 独立会话并发及重新分析竞争已验证；PostgreSQL 执行证据仍待补。
- [x] 增加账号隔离反馈事件、单品明确排除、幂等撤销和基于保存情境的反馈影响。
- [x] 增加穿着事件、成员快照、撤销及30天观察门槛报告；记录不足时不声称长期闲置。
- [x] 将衣橱/偏好/反馈 revision 纳入缓存与快照过期判断；旧快照可读，迟到结果不能覆盖新请求。

## M3：使用成本、恢复和效率

- [x] 增加不含用户数据的游客样例、登录后输入接续和首次录入引导。
- [x] 默认购买和上传使用 v2，刷新后只恢复最新选定结果；旧轮询、分页和切换账号后的迟到请求不得覆盖当前结果。可信衣物条件与后端一致，待确认结果有明确确认入口。
- [x] 将购买历史与可恢复购买任务拆为独立组件，并提供购买历史、修正、决定、反馈和穿着界面；`App.tsx` 保留其他主流程页面和路由编排。
- [x] 服务端游标分页和过滤覆盖衣物、搭配、候选、任务、反馈、穿着；前端已接入衣物、搭配、候选、购买反馈、穿着记录，以及衣物上传/购买分析任务的首屏恢复与后续加载。
- [x] 统一浏览器图片压缩/校验入口，最多 3 项并发，逐项重试；实现 401 处理、请求取消和乱序保护。批量删除保留失败项并呈现逐项结果。
- [x] 加入任务阶段/provider/重试/成本指标与敏感数据脱敏。阶段累计耗时和单次供应商操作耗时持久化，任务详情及购买任务卡展示 provider、token 用量和供应商返回的成本；成本只使用有效回报，不推算价目。
- [~] 导航焦点和部分键盘路径已有行为测试；真实浏览器购买页在 375px 及 640px（1280px 的 200% 等效重排）无横向溢出，移动导航键盘激活通过。实际浏览器缩放、读屏及跨所有页面的完整验收仍未完成。
